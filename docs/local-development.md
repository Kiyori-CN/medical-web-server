# 本地开发

## 权威流程

`D:\10_Project\medical-web-server` 是唯一开发工作区。源码、文档、数据构建、测试和浏览器验收都在本地完成；GitHub `main` 是唯一发布源；服务器只做部署镜像、生产运行和最终验收。

## 开始任务

```powershell
cd D:\10_Project\medical-web-server
git status --short --branch
git fetch origin --prune
git merge --ff-only origin/main
```

存在未提交修改时必须保留并避免覆盖。禁止清理 `data/`、`knowledge-base/` 或 `state/`。

## Python 环境

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

本地秘密只放在被忽略的环境变量、设置数据库或 `.env.local`。不得把真实 API 密钥写入 `.env.example`。

## 构建数据

```powershell
.\.venv\Scripts\python.exe scripts\build_catalog.py --activate
.\.venv\Scripts\python.exe scripts\init_app.py
```

`build_catalog.py` 只读扫描 `data/` 并写入新的不可变 build。只有完整性、外键、统计和报告全部通过后，`--activate` 才更新 `knowledge-base/current.json`。

`init_app.py` 初始化：

- `state/app.sqlite3` 的账号、头像、会话、文件刷题状态、收藏、错题、私有笔记和评论表；
- `state/settings.sqlite3` 的网站与模型设置；
- `state/settings.key` 的独立加密 key。

全新状态库不创建默认账号。首次打开网站时通过一次性页面创建首位管理员。

## 启动

```powershell
$env:FLASK_ENV = "development"
$env:SECURE_COOKIES = "false"
.\.venv\Scripts\python.exe app\backend\main.py
```

本地地址：`http://127.0.0.1:5001/`。

## 语义向量

先在管理员设置页保存并测试已轮换的嵌入配置，再执行：

```powershell
.\.venv\Scripts\python.exe scripts\build_vectors.py --activate
```

脚本从加密设置库读取密钥，按批次 flush 矩阵并原子更新进度。改变 catalog、API URL、模型或维度会生成新的 vector build。stdout、manifest 和 Git 中不得出现密钥。

管理员界面的“模型管理”将嵌入模型和大语言模型分开保存。API 密钥输入后会在短暂停顿时调用临时模型发现接口，未点击保存也可以选择上游模型；临时密钥不会写入设置库。头像上传先在浏览器完成正方形裁剪和 WebP 压缩，服务端再统一转码并写入 `user_avatars`。

AI 页面可在本地登录后验证会话新建、选择、重命名、删除和消息恢复。问答使用非流式 LLM 请求与最多 6 条题库引用；答案解析解锁后，刷题页的“AI 解析这道题”应带 occurrence/collection 上下文进入 AI 页面。每条 AI 回答应提供复制、继续追问和最后一条回答重新生成操作，输入框生成中应显示停止按钮；点击停止后不能把迟到响应插入消息列表。API 重新生成必须要求登录与 CSRF、原位替换 assistant 消息、保留消息数量/ID，并拒绝其他账号或没有最后回答的会话。未配置 LLM 时应显示可恢复的配置提示，不应阻塞题库、搜题或刷题。

论坛页面需验证两个默认分区、主题发布、分区切换、关键词搜索、主题详情、回复、空状态和分页；选择某条回复后表单必须显示/取消回复对象并提交 `parent_reply_id`，详情显示父回复作者，已删除父回复不可继续作为目标。正文中的有效 `@用户名` 进入“回复与@”消息分类，重复提及、自己、停用/不存在账号以及同时为楼主/父作者的账号不得产生重复通知，单条回复最多处理 20 个唯一提及。作者可以编辑/删除自己的主题与回复，其他普通用户的同类请求返回 403；主题/回复支持互斥的赞同、反对和再次点击取消，自己的内容不显示互动按钮；相同赞同重复请求不重复通知。系统管理的论坛管理需验证关键词、类型、状态筛选，隐藏后普通用户不可见、恢复后重新可见、删除后不可恢复、隐藏主题下的回复不可单独恢复、2–500 字审核原因、CSRF、普通用户 403 与审计顺序；管理员从主题详情跨作者编辑或删除同样必须留痕。作者可进入公开主页并继续关注/私信；论坛主题/回复出现在对应个人动态，论坛获赞计入公开统计，回复、提及和赞同进入对应消息分类。手机端主题列表、管理筛选、审核卡片、审计记录、发布/编辑表单、互动按钮、回复对象提示和回复区域不得横向溢出。

系统管理的题库管理页需验证 JSONL/CSV 两种导出。管理员响应应包含 occurrence 原题版本、collection 路径、选项和解析，普通用户返回 403；可选 `collection_id` 只能输出该文件。测试须覆盖流式响应头、CSV UTF-8 BOM 与公式中和，导出过程不得写入 catalog、向量或用户 state。

“我的 → 下载数据”需验证登录用户可以下载 JSONL/CSV 学习数据，且只包含当前账号的收藏、错题、私有笔记、规范题/文件题进度、练习会话和逐题作答记录。测试应覆盖未登录 401、非法格式 400、`private, no-store`/`X-Accel-Buffering` 响应头、CSV BOM 与公式中和，以及切换账号后的数据隔离；导出只能只读 state，不能写入 catalog、向量或设置密钥。

导入预检需覆盖 XLSX、CSV、JSONL、JSON、自动映射、手动映射、结构化 options、无效 JSON 行、空题干、错误扩展名、路径穿越 ID、16 MB 文件上限和 JSON 413。XLSX 测试至少包含多工作表、工作表行定位、共享/内联字符串、损坏或重复容器、DTD/实体与解压体积拒绝，且确认标准库流式解析只读缓存值、不加载外链或成为 API 启动依赖。上传后只能在 `state/import-staging/` 看到随机目录；删除暂存后目录消失，catalog/向量指针和 `app.sqlite3` 不得变化。手机端题库管理的文件选择、映射和样例表格不得造成页面横向溢出。

向量生命周期由 `/api/admin/vectors` 管理：构建请求启动独立 `medical_app.vector_task` 进程，状态写入 `state/vector-operation.json`，构建中断可续建；同配置 catalog 更新时按 `question_id` 增量复用旧向量。删除接口必须收到确认字段，只清除激活指针与向量制品。

## 开发粒度

每项改动应形成完整可验证闭环，例如：

- 一个导入或质量规则；
- 一个 API 与其安全测试；
- 一种刷题模式；
- 一组响应式 UI 改进；
- 一项部署或文档规范。

功能、API、路径、安全边界或部署方式变化时，同步修改 README、PROJECT、AGENTS、对应 docs 和项目技能。

## 提交与推送

本地 `FLASK_ENV=development` 启动时启用 Flask 自动重载；如果使用生产环境变量或外部进程管理器运行本地服务，修改后端 Python 文件后必须重启该进程，避免继续使用旧内存代码。每次发布前端资源时同步更新 `index.html` 中的提交哈希查询参数，避免浏览器继续使用旧 JS/CSS；已有页面仍需刷新一次。

用户已授权本项目最终发布和部署时，仍应精确暂存源码与文档：

```powershell
git status --short --branch
git diff --check
git diff --stat
git add <明确文件>
git commit -m "<明确说明>"
git push origin main
git rev-parse HEAD
```

不要使用 `git add .` 无差别加入本地文件。确认 `data/`、catalog、state、日志和密钥均未进入提交。

反馈闭环的本地验收至少覆盖：未登录 `POST /api/feedback` 返回 401；缺少或错误 CSRF 返回 403；普通用户不能读取或修改 `/api/admin/feedback`；不同账号提交记录在管理员列表中保持隔离；非法类型、少于 2 字或超过 4000 字返回 400；管理员可按关键词/状态分页并在 `open` 与 `resolved` 间切换。
